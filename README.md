# VESTIGO

## Вход по логину и паролю

Доступ к страницам, API, оригиналам документов, аналитике и экспорту требует входа. Аккаунты разные, но права у всех одинаковые: полный доступ к общей базе, без ролей.

При первом запуске откройте `/login`. Одноразовый код настройки находится в `data/first-account-code.txt` на компьютере/сервере платформы. Введите этот код, придумайте логин и пароль от 12 символов. После создания первого аккаунта настройка закрывается; общедоступной регистрации нет. Новые аккаунты создаются вошедшим пользователем в разделе «Аккаунты» с подтверждением его текущего пароля. Там же можно сменить свой пароль. Кнопка «Выйти» завершает сеанс.

Пароли не хранятся открытым текстом: используется scrypt с индивидуальной солью. Сессия хранится в HttpOnly/SameSite=Strict cookie, в БД — только хэш случайного токена. Максимальная длительность — 12 часов, проверяется также неактивность. Смена пароля завершает прежние сеансы этого аккаунта. В журнале и заданиях обработки сохраняется реальный автор действия.

Для сетевого сервера обязателен HTTPS; после настройки доверенного HTTPS-прокси установите `VESTIGO_HTTPS=1`, чтобы cookie передавалась только по защищённому соединению. Авторизация не заменяет шифрование диска, резервные копии, защищённую сеть и нагрузочную приёмку. По текущему решению все пользователи видят все дела, не только свои.

Подробности и результаты проверок: `AUTH_ACCOUNTS_2026-10-21.md`. При передаче чистого проекта не включайте рабочую папку `data` с материалами, аккаунтами, сеансами и кодом первоначальной настройки.

Vestigo — самостоятельная локальная информационно-аналитическая система для сопровождения исследований по статьям 214 и 216 УК РК.

## Текущий рабочий этап

Реализован независимый базовый контур:

- отдельный порт `http://localhost:3200`;
- отдельная SQLite-база `data/vestigo.sqlite`;
- семь основных разделов интерфейса;
- рабочее создание и архивирование дел;
- рабочее создание эпизодов;
- десять групп документов, включая служебную переписку и нераспределённые материалы;
- определение группы/вида по локальным правилам с ручной проверкой неоднозначных случаев;
- сохраняемая фоновая очередь принятых документов, отдельный обработчик и восстановление прерванных заданий;
- пакетная загрузка оригиналов с привязкой к делу и эпизоду;
- серверный SHA-256, контроль точных дублей и проверка целостности при скачивании;
- реестр документов с поиском по названию, виду и источнику;
- журнал действий и версионирование карточки дела;
- связанная модель данных документов, операций, расчётов, проверок, возмещения и отчётов;
- реальные показатели главной панели без демонстрационных записей;
- автоматические тесты целостности базовой модели.
- аналитический интерфейс Qaztin, адаптированный для собственных данных Vestigo: `/analytics`;
- поиск объектов, карточки, ЭСФ и налоговые формы, риски, графы и поиск по схеме;
- редактируемый Excel-экспорт схемы;
- автоматическое чтение загруженных документов в контексте выбранного дела;
- просмотр исходных строк и текста, настройка столбцов нестандартной таблицы;
- реестр извлечённых операций дела, кандидаты связей ЭСФ с платежами;
- вопросы проверки с объяснением, ссылками на источники и журналированием решений;
- журнал аналитических загрузок, удаление и локальный пересчёт.

Qaztin не используется как источник рабочих данных. Прямая интеграция с КГД отсутствует.

## Запуск

1. Установить Node.js 22.13 или новее.
2. В каталоге Vestigo выполнить `npm install`.
3. Для обработки таблиц создать отдельную Python-среду: `python -m venv .venv` и `.venv\Scripts\python.exe -m pip install -r requirements.txt`.
4. Запустить `START_VESTIGO.cmd` либо `npm start`: веб-сервер работает на 3200, внутренний сервис аналитики/экспорта — на 4418, дополнительно запускается фоновый обработчик документов.
5. Открыть `http://localhost:3200`; аналитика выбранного дела доступна по ссылке «Аналитика и граф дела».

Очередь и план подготовки к серверу АФМ описаны в `docs/AFM_PREPARATION.md`. Текущий этап не подтверждает промышленную готовность на 500 сотрудников. Отдельно запустить обработчик для существующей установки можно командой `node scripts/processing-worker.mjs` из каталога проекта; данные должны указывать на ту же базу, что и сайт.

## Важно

Работают дела, хранение оригиналов, чтение поддержанных таблиц, текста Word/PDF и анализ операций внутри выбранного дела. Для сканов PDF и изображений добавлены локальное OCR, реквизиты-кандидаты и предложенные границы документов со сверкой. Настройка и реальные ограничения — в `docs/AUTO_DOCUMENT_ANALYSIS.md` и `docs/CASE-ANALYSIS.md`. Прежняя общая аналитика Qaztin на `/analytics` сохранена отдельно; документы дела не передаются туда автоматически. Полноценная бухгалтерская сверка 1С, юридически согласованный расчёт ущерба и генерация экспертных отчётов ещё не реализованы. Полноценная аутентификация и разграничение доступа между пользователями также не внедрены; текущий сервер предназначен для локальной разработки.
